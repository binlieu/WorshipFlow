## Decisions

- Single source of truth: `Theme.fullScreen` / `Theme.lowerThird` are built from `SceneStyles.standard`. `SceneStyles` stays for the stage layout and the legacy `styles:` entry point, which builds its themes from the styles it is given. `Theme.mediaFallbackColor` is the colour under the video.
- Built-in theme ids are fixed literals (`57465448-454D-4501-...01` full screen, `...4502-...02` lower third), pinned by a test.
- `TextBlock` also carries `verticalAlignment` (the old audience layout is bottom/top aligned), default `.center`.
- Composer rules: stopped show is empty (audience black, broadcast clear) with no props. Hidden background layer gives black on audience and clear on broadcast. A `.image` background sets a black colour under it. Props are images drawn `.fit`; stage ignores theme, Look and props (returns the old stage scene). Presentation theme is unused for now (nil) because presentations have no theme field yet.
- Resolver: an unknown id is skipped to the next level; broadcast never inherits the presentation theme.
- Compositor: draw order colour, video, background image, text, overlays (scissor reset before overlays). Opacity is applied in the fragment shader on the premultiplied value. Images are decoded by ImageIO to premultiplied sRGB BGRA (thumbnail API, longest side capped at 4096, EXIF orientation applied) and uploaded to `.bgra8Unorm`, like text.
- Cache: keyed by path, entry stores modification date, re-checked at most once a second; reload on change; missing file retried when it appears. Bounded to 64 images and 256 MB, least recently used out, never an image used by the current frame. `imageDecodeCount` and `unavailableImagePaths` (lock-guarded, readable from any thread).
- Decoding: `renderImage` (tests/snapshots) decodes synchronously. `encode` (live path) defaults to `.background`: the decode runs on a utility queue and the image is skipped until ready, so the render thread never waits. A newly added prop therefore appears a few frames late. Each output's compositor keeps its own cache, so a file is decoded once per output.
- Scenes are now per screen profile (`PublishedScenes` keyed by profile id), not per role, because Look and theme are per screen. One immutable snapshot, one publish per change (`lookChanged`). Video source is given to every non-stage screen (a broadcast theme may choose `.media`).
- Persistence: `looks.json` beside `screen-profiles.json` (`LookLibrary`: looks, selected Look, props with security-scoped bookmark data). Not written in a soak; unreadable file is left alone. Look deletion keeps at least one Look. "New" copies the current Look.
- Operator window shows unreadable image paths (files checked with `isReadableFile` plus what outputs reported), and a note beside a prop whose file is unreadable.
