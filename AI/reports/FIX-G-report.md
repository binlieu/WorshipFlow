### What changed, per item

1. `LiveMedia.playing(override:state:at:)` (OperatorCore) is what the registry now plays: a background hidden by Clear background or Stop is not in the set, so no player runs and nothing is heard; Go Live, Next and Previous bring it (and its sound) back; Blackout keeps the player and the existing Blackout flag silences it (unchanged). The clip over the words is untouched. `AppModel.effectiveMedia()` uses it.
2. Migration **v11**: `ALTER TABLE slide ADD COLUMN background TEXT`. A column rather than a child table: one background per slide, it goes with the row (slide delete, presentation delete, re-flow) with no foreign key to keep. It moves every `slideBackgrounds.<presentation>` appState entry into its slide rows and deletes the entries; entries for slides or presentations that no longer exist, and unreadable ones, are dropped; nothing else is touched. Re-flow carries it by the same match as notes and objects and `ReflowLoss.hasBackground` names one it cannot (the re-flow sheet says "its own background"). The package carries it (`SlideEntry.background`: asset id, kind, duration and a relative `file`; the bin item is also in `mediaAssets`); import writes the column, points the slide at an existing bin entry that uses the same file, and a package without the field still imports. `MediaModel.removalImpact(_:)` lists the slides before a bin item is removed (the bin's "Remove from bin" asks first); the slides keep the choice and their thumbnail shows a warning triangle.
3. `WorkspaceModel.importingProgram { ... }` writes waiting drafts first, runs the import, drops drafts of the presentations it replaced and reloads. `LibraryStore.backUp(beforeImportAt:keeping:)` uses SQLite's backup API into `Backups/` beside the library (name with the UTC date and "before import", newest five of that name kept, other files untouched); the importer calls it when something is replaced and refuses to replace (`backupFailed`) if it cannot. `ProgramLiveContext` keeps a live presentation as "both" and says so (`keptBecauseLive`, a warning); the result says where the backup is (`backupURL`, the sheet's message).
4. The bookmark is resolved by `FolderAccessing.resolve` with `.withoutUI` and `.withoutMounting`, only off the main actor (a detached utility task in the scan); the real watcher opens the folder on a utility queue; every directory listing was already detached. `load(waitForScans: false)` is what launch uses.
5. `MediaModel.setHotAssets` keeps an item that is on a layer registered while it plays (`retainedHot`, released when the layer lets go); files known complete at a size are not held back again; a listing error other than "missing" keeps the last items and shows "not answering"; a remembered background that is a hot-folder item is restored when its folder first lists it (`pendingBackgroundID`) unless the operator chose something else.
6. One scan at a time per folder (`inFlight`, a request that arrives asks for exactly one more); `requestRescan()` for the timer and the watcher; unreadable files are remembered and retried after 2, 4, 8, ... up to 64 scans (a size change resets), and do not count as "held back"; the probe cache is per folder and pruned every scan; 2,000-item cap with a notice; `playFolder` skips an unreadable file, reports it once, and stops with a message when none can be played.
7. Free space on the library's volume must cover the files to copy plus a margin (`spaceMargin`: a tenth, at least 64 MB), else `notEnoughSpace`; `chunkedCopy(limit:)` stops before writing the piece that would go past the manifest's size (`mediaDamaged`).
8. `ProgramPackageContents.open` refuses a custom theme with a built-in id (`builtInThemeClash`). It also now refuses a media file with more than one name on disk (hard link), as a safety addition the review's test list implies.
9. `MediaPreviewModel.sessionPreview` starts muted; the app's panel has a speaker button and a line (`heardLine`) naming the default output; `itemSentLive(_:)` pauses the preview when its own item is sent (`performDockAction`).
10. While a show is live a theme or Look in use is kept beside the imported one (`insertCopy` with a warning). A Look entry records each screen's role (`roles`); import maps by role (a screen already matching a local profile of that role keeps it), lists roles this Mac lacks in the result's warnings, keeps a screen with no recorded role as written. The summary lists slide actions by kind and count; the sheet shows them.
11. `MediaCollector` hashes on a utility dispatch queue and polls `isCancelled` between and inside files; `ProgramExporter.plan(... isCancelled:hooks:)`; the sheet cancels planning on close, Cancel or a new playlist; `write` refuses a destination inside the library folder (also through a link).
12. The scan resolves the bookmark first and scans the path it leads to; the folder's new path and a refreshed bookmark are saved and the new path is watched; the folder keeps its id.
