## What must be added to the package for the per-slide background (MEDIA-010, migration v11)

`slide.background` (JSON of `MediaSelection`: `assetID`, `kind`, `duration`) now exists in the media agent's work. A package written by this build carries no per-slide background, and an import writes none; a slide in a later package with a `background` field is read and the field ignored (tested with an extra slide field). To carry it: add `background: MediaSelection?` to `ProgramDocument.SlideEntry` (optional, omitted when nil); in `ProgramSnapshot.presentation` copy `slide.content.background` and add its asset (with its file through `MediaCollector.reference`) to `mediaAssets`; include `background` in `ProgramSnapshot.ContentKey.SlideKey` (until then two presentations that differ only in a slide background compare as identical); in `ProgramImportWriter.write` add the `background` column to the slide `INSERT` (only when the column exists) and collect the asset ids in `ProgramImportPlanner` like action assets. The format version can stay 1 (additive).

## Decisions and deviations from the brief

- **A new target plus a small door in Persistence.** `ProgramPackage` (with `ProgramPackageTests`) holds the format, planning and file work; `Persistence/ProgramDoor.swift` adds an `@_spi(ProgramPackage)` door (`programRead`, `programWrite`, `libraryFolder`) in the pattern of `CueStore` and `ScriptureStore`, so the import can write every table in one transaction through the library's one connection pool. `Package.swift` and `project.yml` were edited (allowed).
- **A scratch package for testing.** Because the real package's test targets include the media agent's tests that did not compile for a while, my target was built and run in a scratch package over the live sources (`scratchpad/lib005pkg`, nothing in the repository). Final verification was the real `check.sh`.
- **Looks are carried only when a slide action selects them** (`look.select`), and the custom themes those Looks or the presentations use. Playlist items do not otherwise "use" a Look, so the brief's "the themes and Looks those items use" is read that way. Built-in themes are not written.
- **Media bin entries** that slide actions play (`media.playForeground`, `media.setBackground`, `audio.play`, `audio.stop`) are carried with their files, because those are the playlist's "backgrounds, foregrounds, audio and clips". Props and the rest of the bin are not carried (props are global and have no per-program state); the export sheet warns when actions use macros, props, timers or stage messages, which are also not carried (known issue KI-096).
- **New presentations go into the first library** (or a library named "Library" is created in the same transaction). The brief did not say.
- **A conflicting playlist is a conflict too**, so with "Keep both" the playlist becomes "<name> (imported)" and plays the imported copies, rather than leaving the library's own playlist pointing at the old song. With "Use the imported one" a presentation's slides are replaced in place; a playlist item in another playlist that used one of its arrangements loses that arrangement (KI-098).
- **Conflicts for themes and Looks follow the same single answer**, which the brief did not spell out. Media bin entries are matched by id and never overwritten.
- **Identity.** "Id and content match" compares title, kind, theme, per slide the text, notes, section name, objects (image bytes by checksum) and actions, and arrangements by name; ids of slides, sections and arrangements are ignored. Media is compared by SHA-256, so a picture counts by its bytes, not its location.
- **Export reads every media file twice** (hash for the plan, copy or clone for the write); a very large video makes the plan step slow (KI-098).
- **`App/Info.plist` is new** and generated by XcodeGen from `project.yml` (`info:` block, with `CFBundleShortVersionString` and `CFBundleVersion` taken from the build settings as before). `WORSHIPFLOW.xcodeproj` is regenerated by `check.sh`.
- **Debug-only exercise hook** (`UISnapshotProgram.swift`, `UI_PROGRAM_EXERCISE`), in the pattern of the existing `--ui-snapshots`; it is compiled out of Release and runs only with the variable set. `ProgramTransferModel.export(_:to:replaceExisting:)` was split out of the save-panel method so the hook can write without a panel.
- `docs/14-current-status.md` and `docs/15-agent-handoff.md` were not edited (the brief lists the other five documents; the media agent edits the same area). The next safe task for the coordinator is to update them with both slices.
