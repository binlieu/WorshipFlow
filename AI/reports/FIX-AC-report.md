## A. KI-286: Clear words no longer silences a video object: done
- Code did: Clear, Clear all and Blackout all went to `ObjectVideoPlayers.apply(_:hidden:)`, which muted every held clip. The show state is identical for Clear and Clear all (an existing test pins `viaClear == state`), so the player could not tell them apart.
- Failing tests (old code): `FIXAC_ObjectVideoSoundUnderClearTests` and `FIXAC_ClearedAllFlagTests` did not compile on the old code (`silences`, `apply(_:hidden:silenced:)` and `isClearedAll` did not exist); that is the failure, by design: the old code had no way to keep a held clip audible.
- Change:
  - `ObjectVideoPlayers.silences(_ state:, clearedAll:)` = Blackout, or cleared with Clear all pressed. New `apply(_:hidden:silenced:)`: a held clip is muted when `silenced` or when its own request is muted; hidden and not silenced keeps it playing and heard. The two-argument `apply(_:hidden:)` is kept and means silenced (so Blackout and the FIX-X and FIX-Y tests are untouched).
  - `WorkspaceModel.isClearedAll` (set when Clear all hides the show, kept by a Clear words over it, cleared when the show is no longer cleared: a new slide, lift, Stop), set before `onShowChange` runs for the same command. `ShowState` is unchanged.
  - `AppModel.syncObjectVideos` passes `silenced: ObjectVideoPlayers.silences(show, clearedAll: workspace?.isClearedAll ?? true)` (a soak run with no workspace is taken as Clear all, as before).
- Unchanged and tested: Clear all, Blackout silent; Blackout over Clear words silent, and heard again when Blackout lifts while still cleared; a muted object stays muted; un-clearing keeps the same player (no restart); Stop closes. What is drawn under Clear words is not changed.
- Existing FIX-Y test that pins silence under a clear: `FIXY_ObjectVideoMarksAndClearTests.clearKeepsThePlayersSilencedAndUnClearingDoesNotReopenThem`, assertion `#expect(players.isMuted(r.assetID) == true)` after `players.apply([], hidden: true)`. It still passes unedited because the two-argument form still means silenced (it now describes Clear all and Blackout). Nothing to replace; the coordinator may rename it. The report text of FIX-Y item 2 ("objects are silenced under Clear words") is superseded.
- Not verified: `--silent-audio` does not reach video-object players at all today (it only applies to the audio cue engine and the bin preview); this was not changed and not tested. Hands-on 1.

## C. LIB-004d: the test build carries the KJV: done in code and script; nothing run for real
- Script: `scripts/lib-bundle-translations.sh` (sourced by `package-test-build.sh`): `bundle_translations Bibles "$APP"` copies only `KJV.json` (allow-list of one exact name; a link is not followed) into `Contents/Resources/Bibles/`, prints one line ("No Bibles/KJV.json on this Mac: the app is built without a bundled translation.") when absent. The app is then signed again (`codesign --force --sign - --preserve-metadata=identifier,entitlements,flags,requirements`, same ad-hoc identity), `check_bundled_translations` lists `Resources/Bibles` and the script stops if anything but `KJV.json` is there, then the existing `codesign --verify --deep --strict`. `check.sh` and Debug and Release builds do not touch `Bibles/`. The real packaging script was not run (re-signing with preserved metadata, and the zip, are therefore not verified).
- Script tests: `FIXAC_BundleScriptTests` run the helper in temporary folders with invented bytes (KJV.json plus NKJV.json and other names: only KJV.json arrives; absent file gives one line and no folder; a link is not followed; the check fails on any stray entry, hidden ones included). They failed with the helper absent (status 127) and pass with it.
- App: `ScriptureModel.offerBundledTranslations(in:)` (new `ScriptureModel+Bundled.swift`), called once from `AppModel.startWorkspace` after the workspace has loaded, in its own task. It lists `.json` files of `Resources/Bibles`, reads and decodes each off the main actor (same 64 MB cap and `TranslationLoader.decode`), and imports through `ScriptureStore.importTranslation(replaceExisting: false)` (the same validation as a picked file). A quiet success only reloads the list (and makes it the first translation when there was none, as an ordinary import does); no alert, no message. A failure is set as the import status shown at the translations list, in the existing style ("“KJV.json”, which came with this build, could not be added. ... You can still import a translation file of your own here."), or as `translationsError` if an import is running.
- Where "already offered" is kept: the library's existing key/value state (`LibraryStore.state(for:)`, the same place as the saved scripture choices), key `scripture.bundledOffered`, a JSON list of lower-case file stems. Smaller than a marker file, no migration. Recorded on success and when the library already has the id; not recorded on failure, so a corrected file is taken at the next launch. A file already in the list is not even read.
- Tests (`FIXAC_BundledTranslationTests`, a few invented verses made in the test): first launch imports and stays quiet; second launch does not read or import; removed is not put back (same model and a new one); a library that has the id is untouched (name and verse count kept, and removal later is not undone); a damaged file reports with the file name, imports nothing, leaves Import available and is retried with a good file next launch; no folder, a missing folder or an empty one does nothing and records nothing; only `.json` files are offered. They failed to compile on the old code (no `offerBundledTranslations`).
- Translations view: it shows `copyrightLine` (the file's own copyright text, or "No copyright line came with this file."). It does NOT show the file's licence text anywhere (`StoredTranslation` keeps `licence`, no view reads it). I added nothing; this is a decision for the coordinator before the KJV ships to a tester.
- Not verified: a real launch of a packaged app with the file, the real KJV file (never opened, per the rules), that the import stays off the main thread under load (it is built that way: decode in a detached task, import on the store's queue; not measured), and the size of the packaged zip.
