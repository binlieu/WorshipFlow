## Decisions

- `ShowCommand` has one addition, `.select(index:)`, so selecting a slide changes preview only. `ShowState.selectedIndex` follows the live slide only while the live and preview decks are the same presentation. `quickEdit` also updates the preview copy when it is the same presentation. Next at the end of a cleared deck does nothing; Next from idle starts at slide 0.
- `SceneComposer.scene` has an extra defaulted `styles:` parameter; all default styles are in `SceneStyles.standard`. Stage shows current primary plus secondary (one layer), next primary, and the clock.
- Router checks in order: operator display, missing, in use (first in profile order keeps it). Faulted screens claim no display.
- Coordinator: on a display change it stops only outputs whose assignment changed. **Auto-resume**: a screen faulted for a missing display (or whose output stopped by itself while its display was gone) resumes on that same display when it returns; it is never moved to another display. A screen stopped by the operator, or a closed window, stays stopped until restarted. `start()` also arms auto-resume for a display that was missing at start, so plugging it in later opens that full-screen output without a click. Keep or drop that: coordinator's call. Editing a profile restarts only screens whose role, destination or enabled flag changed (a rename restarts nothing).
- Stop (button) empties the screens (audience black, no video; stage dark; broadcast clear) and keeps the outputs open. Separate "Open screens / Close screens" button starts and stops outputs and the video. Go Live or Next from stopped opens the screens if they are closed. The brief did not say whether Stop closes outputs; this is my reading of "screens go empty".
- One publish: `AppModel` composes the three scenes into an immutable `PublishedScenes` and swaps it into a lock-guarded `SceneBox`; every output reads that one snapshot (NFR-04). Render threads never touch the model. Clock text republishes when the minute changes.
- KI-008: `OutputTarget.isOccluded`; the coordinator reports `.hidden` and the panel shows a "Hidden" status with the counters shown as paused.
- SleepGuard: `update(runningCount:)` (idempotent) holds PreventUserIdleDisplaySleep and PreventUserIdleSystemSleep while count > 0; backend injected. Real IOKit backend.
- Key monitor only acts for real windows (`canBecomeMain`), so it ignores menus, panels and open dialogs, and ignores keys while a text field is editing. Return is Go Live.
- No alert or sheet is ever created. The background video chooser uses a non-modal `NSOpenPanel.begin`, a normal panel from the operator window.
- Profiles persist as JSON in `~/Library/Application Support/WORSHIPFLOW/screen-profiles.json` (interim; the SQLite table comes later). Display ids are CGDirectDisplayIDs; whether they stay stable across replug/reboot was not checked. A soak never writes this file (fixed after review; `soak` is parsed in `init`). An unreadable file leaves the file alone and uses defaults.
- Soak uses one in-memory Audience profile (display from `--screen`, else a window); the operator display is not protected in a soak, as before. Exit codes: 0 completed, 1 failure/no frames, 4 hidden with zero frames presented, 2/3 as before.
- `AppModel.coordinator` is `lazy`, not an implicitly unwrapped optional. No force unwraps added.

## Offscreen four-output benchmark

`FourOutputBenchmarkTests`: one Compositor, one command buffer per frame with four 1920x1080 BGRA passes (audience, stage, broadcast, audience), `waitUntilCompleted` each frame, 10 warm-up frames then 600 timed, Debug build. Text cached after warm-up, no video layer. Ceiling asserted: mean < 16 ms.
- Check.sh run: mean 0.637 ms, p99 0.856 ms, worst 5.524 ms.
- Earlier standalone runs: mean 0.574 / worst 1.348 ms and mean 0.655 / worst 1.413 ms. Worst-case varies run to run.
Measures composition and GPU completion only: not presentation, video decode, or display sync.
