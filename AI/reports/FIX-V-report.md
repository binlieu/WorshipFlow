## Item 3, M3: section order edits (reproduced)

- Failing output before (three tests with the old position API, run alone): two quick removes at rows 1 and 3 left `[Verse 1, Chorus, Verse 2]` (the Bridge removed, the Chorus kept, matching the review); two quick moves and a remove plus an add lost one of the two edits.
- Change: `SectionEntry` (section + occurrence) is the identity. New `removeSection(_ entry:)`, `moveSection(_ entry:, by:)`, `moveSection(_ entry:, before:)`; `sectionEntries(of:)`. Every order edit (add, rename, remove, move) runs through one serial gate (`editSectionOrder`): after the previous edit finished and the draft flush was awaited it **reads the order from the library**, finds the entry, computes, writes, reloads. A gone entry or order is a no-op with a message in `lastError` ("...no longer in this order, so nothing was changed"). The old position methods stay (existing tests) and now resolve the entry at the call, then run by identity. The sheet (`SectionOrderSheet.swift`) draws rows by entry and passes entries (drag passes the entry it was dropped before).
- Limit, stated: with a repeated section, if the operator clicks "remove the second Chorus" after the first Chorus has gone, that entry no longer exists (the other Chorus is now occurrence 0), so the click does nothing and says so; it never removes a different section.
- No undo stack exists for section orders; each action is one atomic write. Tests `FIXV_SectionOrderTests` (8). One test was racing two tasks with order-dependent results and failed once in a loaded full run; replaced by sequential steps, the order-independent races stay.

## Item 4, M2: retired outputs (reproduced)

- Failing output before: after 12 open/close/profile-change cycles `retiredCount` was 28 and none of the stopped outputs were deallocated.

No SDI test touched; the SDI/output/coordinator suites pass.
- Tests `FIXV_RetiredOutputTests`: display cycles leave `retiredCount == 0` and weak refs nil; a slow-teardown target is held while closing and released after; a waiting stop still waits.
