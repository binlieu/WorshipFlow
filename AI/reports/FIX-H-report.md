## Items

1. **Loop vs operator's clip (done).** The loop's logic is `MediaItemRunner` (OperatorCore) with a clock injected and two ports: `ForegroundPort` (the media bin's own model conforms) and `AudioPlayerPort` (the audio model). `MediaModel.foregroundStarts` counts every start on the foreground (bin, dock, cue, folder play, loop); the loop remembers the count after its own start, so a clip the operator plays, even the same picture again, is never replaced; the loop then ends and calls `onLoopEnded`, which the app wires to `WorkspaceModel.mediaItemEnded()`. Stopping the loop stops only the loop's own picture. The App's `MediaItemPlayer` is now a thin wrapper; the app's half-second timer calls `tick()` (also for a video loop, which had no timer). Tests: 13 in `FIXH_LoopRunnerTests`.
2. **Blackout over media (done).** Decision applied: taking a file, loop or sound live ends Blackout, Clear and a hidden background without moving the slide (`ShowCommand.liftHolds`, new in Domain). A slide taken live already does this. Tests: 2 in `FIXH_MediaItemModelTests` (Next onto a video; Go Live on a video and a loop after Clear and Clear background; a sound after Blackout).
3. **Playlist change with media live (done).** `selectPlaylist` and `deletePlaylist` end the live file or loop first, from `liveMediaCopy` (the item as it was at Go Live), and `endLiveMediaItem` now uses it instead of a lookup in the reloaded list. Next and Previous: when the live item is no longer in the list, the stale file or loop is ended and the normal path runs. Tests: 4.
4. **Retry on a mirror (done).** `OutputCoordinator.restart(slot:)` restarts one output; the card carries its `slot`; `OutputFaultCards.retry(_:on:)` takes an `OutputRestarting` coordinator (a fake that records the slots in the tests, the real coordinator with fake targets in one test: the primary's `startCount` stays 1 and `stopCount` 0); `OutputFaultCards.notes(_:keepingCardsOf:)` drops a "did not reopen" note when its card goes, called from the app's readout update. Tests: 6.
5. **Decoding bypassing clamps (done).** `AnnouncementsSpec` (`secondsPerPicture` is now `private(set)`; custom `init(from:)` clamps 3 to 120, default 8, drops sounds; `pictureIndex` guards zero and takes the remainder in floating point so a huge elapsed time cannot overflow), `TextPropSpec` (custom `init(from:)`: clamped size, default colour and anchor for missing or unknown values), `Prop` (opacity held to 0 to 1, and when decoded). Types UI-005b added with validation in `init` and synthesised Codable: `AnnouncementsSpec`, `TextPropSpec`, `Prop`; `MediaItemSpec`, `LibraryKind`, `PropKind` have no validation to bypass. The program reader refuses a package whose loop time is outside 3 to 120 in plain words ("The loop "X" shows each picture for 0 seconds. A picture stays between 3 and 120 seconds, so the program was not opened. Nothing was imported.") before anything is written. Tests: 6 + 3.
6. **Missing file shows LIVE (done).** `MediaItemOutcome` from the runner; `WorkspaceModel` asks a preflight first (listed and readable, for pictures, videos, loops and sounds), so a bad file changes nothing; a failure after the screens changed (the player refusing) undoes what the model did, clears the live mark and says which file. A sound with no audio player says so. `MediaModel.startForeground` and `AudioModel.start` return the reason; `playForeground` and `play` keep their old behaviour. Tests: 5 in `FIXH_MediaItemOutcomeTests` plus 7 in the runner file.
7. **Keys on focused controls (done).** `KeyRouting.decision(for:focus:...)` over `FocusedElement`; a focused control keeps every key but Escape, which returns focus to the show (`KeyDecision.focusShow`). The old `decision(for:textInputFocused:...)` is unchanged and agrees with the new one where they overlap (a test). The app's key monitor reads `ui.focusedControl` (the custom controls report their own focus through `WFFocusReport`) or the AppKit responder chain (pop-up, button, segmented, slider, tab view). Tests: 10. The checklist says it needs checking with macOS "Keyboard navigation" on.
8. **Custom controls (done, partly by hand).** `WFSlider` is focusable, takes the arrow keys (twentieth of the range), Page Up and Down (a fifth), Home and End (`SliderStepping`), has a spoken name parameter (the three position sliders say "Position"); toggles, checkboxes, segmented controls and pop-ups dim and ignore input when disabled (`ControlEnabledStyle`); `WFSegmented` identifies segments by index (`SegmentIdentity`); segments and tabs carry a selected value, the tab strip a label; every control keeps its role, label, value and actions through the `Toggle`/`Slider` representations. Tests: 6 for the rules. Needs VoiceOver by hand: spoken name, value and the adjust action of each control, and the focus ring and dimmed look (listed in the checklist).
9. **Damaged `targets` (done).** Reads as audience and broadcast, also for a store older than v12. Tests: 2.
10. **Pills and text props (done).** `PropPills` (all three roles always in the row, off = dimmed), `togglePropTarget`, new text props are saved off, `TextPropRules.savedOffNote` shown in the sheet, saving with no screen (or no name) is refused with `TextPropRules.problem`, in the model (`addTextProp` returns nil and sets the error; `saveTextProp` for the Edit sheet) and in the sheet (Save disabled, the reason shown). Tests: 5.
11. **LIVE chip (done).** `WorkspaceModel.liveChipLine` (the live file or loop by its title, else the live slide's words), used by the toolbar chip; `liveMediaMarkID` clears when the loop ended by itself and is what the playlist row marks live; the position for Next and Previous is kept. Tests in `FIXH_MediaItemOutcomeTests`.
12. **Looks for later screens (done).** `Look.screenLook(for:in:)` falls back to the entry of the first screen of the same role that has one; used by the published scenes, the image check, the settings model (including when a toggle on a new screen first writes its own entry) and the app's other readers. Tests: 3. A Look's existing per-screen entries behave as before.
13. **Language names (done).** What the model stores today: nothing. A presentation and a slide hold only primary and secondary text; there is no language code, so there is none to prefer. Labels are now suggestions ("Vietnamese?", in the operator's language) when read from the words, the neutral "First language"/"Second language" otherwise, read once per change of the words (counted by `languageDetections`, tested). `quickEditLanguageNames` (own-language names, used by an existing test) is kept and shares the same reading.
14. **Library from a newer build (done).** `LibraryStore.open` looks at the file read-only first; a migration it does not know throws `LibraryFromNewerBuildError` (found and known steps, plain message with "Nothing was changed", Quit or a different library) before the pool is opened. Tests: 4 (the library file is byte for byte unchanged; an unknown row in the middle counts; a current and an older library still open). The "library problem" screen offers Quit and "Open a different library…" (a file panel, then a restart with `--library`). Recorded as KI-128: builds already made cannot be changed.
15. **Missing tests (done).** Relaunch restore for a sound, a loop, a video and a sermon (selected, never live, no play command); the cue `next`, `previous` and `goLive` paths over the new kinds; the remote state for a media item (a defect found: a sound playing with the screens stopped was not marked live; fixed in `RemoteStateBuilder`).

## Deviations from the brief

- Item 1: there was no named "player port" in the code; I introduced `ForegroundPort` and `AudioPlayerPort` and the media and audio models conform.
- Item 3: Next and Previous fall through to the normal path only when the live media item is gone from the list; at the end of the playlist (step finds nothing, item still there) they do nothing, as before.
- Item 5: the program reader **refuses** an out-of-range loop time (the brief allowed refuse or clamp); decoding elsewhere clamps. `CountdownSpec` (UI-002) was not changed (KI-133).
- Item 6: a preview of a file that cannot be found is now reported through the workspace's error line, not the media bin's.
- Item 7: every AppKit button kind is classed as a button (the routing is identical for them); Escape leaves a control through `window.makeFirstResponder(nil)` and the existing grid-focus request.
- Item 8: see the order slip above; the App-side changes (focus reporting, key handling on the slider, dimming, identity by index) are covered by the build and the pure rules only.
- Item 11: only a loop that ended by itself loses its live mark; a video that finishes on its own keeps its mark and place (Next steps from it), as before (KI-132).
- Item 14: the library records steps, not the app version that wrote it, so the message names both database steps and this build's version.
