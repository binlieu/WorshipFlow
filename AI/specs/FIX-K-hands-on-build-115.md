## Items

1. **"media bin when I click on the movie, the icon clear picture active, expecting clean icon for video active".** Reproduce first and say exactly what happens today: which of the five clear icons becomes enabled when a video in the bin is clicked or sent live, to which layer the clip went, and what each icon's glyph is. Then make it right: the icon that lights is the one that will take that clip off, and its glyph says what it clears. A video on the background layer must not light an icon that reads as "picture". Decision: the background and foreground clear icons take their glyph from what is live on that layer (film for a video, photo for a picture, the plain layer glyph when empty), each with a small "clear" slash or x so it reads as an action; the tooltip names the thing ("Clear background video: Waves, ⌃⌥B"). Only what is live enables an icon; selecting a tile without sending it live enables nothing. Tests on the pure function from live state to (enabled, glyph, tooltip) for every layer and kind.
2. **"Clear menu no need anymore since we have all clear icons".** Remove the Clear menu (the chevron and its popup) from the transport bar. Decision: the plain **Clear** button stays in the transport bar as the design draws it, without the chevron: it clears the words, as `esc` does. Every command the menu held stays reachable from its icon, its key and the app's menu bar. Update the Show mapping file for the transport bar and re-run the rectangle comparison.
3. **"edit tab: text box not be able to dragged or move".** A regression or a gap; find which and say so. In Edit the operator must be able to click any box on the canvas, including the lyric text boxes, and drag it, resize it from the eight handles, and nudge it with the arrow keys (1 point, Shift for 10). For added objects (text, shape, image) this worked before UI-005c: restore it and add a test that would have caught the loss. For the **lyric boxes** (first and second language), which take their frame from the theme today: dragging or resizing one gives **that slide its own text frame**, stored with the slide, shown in the inspector's Position fields, with "Reset to theme position" in the inspector and the box's context menu; other slides are untouched. "Apply to all slides in this song" is a separate explicit action. The frame is in the theme's coordinate space so it holds at every output resolution; Fit still applies inside the new frame. If the slide model needs a new field this task owns migration v14 (additive; a slide with no override renders exactly as today, proven by digest). The override is carried by duplicate, re-flow (by the same match as notes and backgrounds), undo, and program export and import. Editing never changes Live.
4. **"same with edit tab, stage tab also text box doesn't work for the lyric".** Edit half: covered by item 3. Stage half: not in this task (another agent has those files). Write down in the report what the Stage editor needs so the coordinator can brief it after the merge.

7. **"drag and drop feels janky and laggy also sometime sluggish".** The owner did not say where, so measure every drag the app has before changing anything: reordering slides in the grid and filmstrip, reordering playlist items, dragging a song into the playlist, dragging media from the bin onto a slide and into the playlist, dropping files from Finder, dragging objects and handles on the Edit canvas, dragging the column resize strips, the media scrubber and sliders. For each: what runs on the main thread per drag event (database writes, saves, thumbnail or preview renders, full-list diffing, layout of the whole grid, publishing to outputs), measured with signposts or timestamps in a debug build and listed in the report. Then fix the causes: nothing is written or rendered per event that can wait for the drop; drop targets highlight without re-laying-out the grid; previews render at pointer speed or are throttled, never queued up; the drag image is light; lists use stable identity so a reorder does not rebuild every row; no drag ever publishes to an output.
