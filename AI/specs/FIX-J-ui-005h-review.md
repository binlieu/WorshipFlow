# FIX-J: fixes from the independent review of UI-005h (output looks)

Feature IDs: UI-005h (OUT, SLIDE, STAGE). Model: Sonnet. One agent owns the render, theme and stage files; it starts after FIX-I is committed. No migration expected.

The review of commit af3fe42 (2026-11-21) found no critical defect. It found the SDI frame copy by GPU blit sound (synchronised before the copy, no buffer reuse hazard, format unchanged), the matte tests adequate for premultiplied alpha, and migration v13 additive. The decisions on what it did find are below. Test-first, order checked, failing output recorded per item. New tests in `FIXJ_*.swift`. Do not edit existing tests.

## Items

1. **Fix (high): lyrics can run off the top of the screen on the new default audience theme.** The primary block is bottom-aligned and about 494 px tall; four lines at 119 pt and line height 1.2 need about 571 px, and a bilingual two-line slide already wraps to four. Existing songs changed to this look on upgrade. Decision: **fit to the block.** When a text block's laid-out height or width exceeds its frame, the size is reduced in steps until it fits, never below the design's floor of 56 px at 1080 (scaled for other resolutions); first and second language shrink together by the same factor so their ratio holds. If it still does not fit at the floor, it is drawn at the floor, clipped to the title-safe frame, and the slide is flagged: a warning mark on its thumbnail and a line in the editor ("These words do not fit this theme at its smallest size"). Fitting is computed once per slide and theme and cached with the raster, off the main thread, never per frame. It applies to audience and lower-third blocks of built-in and user themes that have "Fit" on; it is on for built-in themes and for the Classic themes it is off (they keep their old behaviour exactly); a user theme gains the switch, default off, so no user theme changes. Tests with the real Inter metrics: a bilingual Vietnamese two-line slide fits inside the frame; a very long line is flagged; every line's ink is inside the frame; the unchanged-user-theme digests still hold.
2. **Fix (medium): the text cache is emptied all at once, and the stage's clock and timer add a key every second.** Evict least-recently-used entries one at a time; keep per-second text (clock, timers, countdowns) in its own small cache so it cannot push out the lyric rasters; rasterise the selected (Preview) slide's layers for each role ahead of Go Live on a background queue so the first live frame is warm. Tests: the cache never drops more than one entry per insert; after 300 clock ticks the current lyric raster is still cached; a counter shows no lyric re-raster across ticks. Put before and after cold and warm frame times in the report (measured with `wf-looks-probe`, not asserted).
3. **Fix (medium): stored theme values bypass the clamps.** `TextStyle`, `GradientBackground` and its stops, `TextPlate` and `AccentBar` decode through the same validation as their initialisers: line height, weight, optical size, radius, opacity and padding clamped to sane ranges, gradient stops sorted and at least two, zero radii refused. Hostile JSON tests for each, including through program import.
4. **Fix (medium): one undecodable row must not hide the rest.** Loading themes, Looks and stage layouts skips a row it cannot decode, keeps the others, and tells the operator once which one was skipped (by name where readable). Test with a row carrying an unknown background kind and an unknown stage element kind.
5. **Fix (medium): moving a stage element leaves its attached parts behind.** The second-language line and the NEXT label are stored relative to the element they belong to and move and scale with it in the editor. Existing stored layouts are read as before (convert on load, in memory; no migration). Test move and resize.
6. **Fix (medium to low): the interface says nothing when Inter is missing.** At launch, after registration, check the font the output themes name resolves to Inter; if not, show one operator notice ("The bundled font could not be loaded; screens are using a system font and line breaks may differ") and record it in the hardware-test environment section. Correct the comment in `InterFont.swift` that says outputs never use Inter.
7. **Fix (low): scripture slide limits use the theme's real metrics** (its line height and the measured average advance of its font and weight), and with Fit on a passage is split so that it fits at the theme's design size, not only at the floor. Say in the report whether saved scripture playlist items store their slides or derive them, and what changes for an existing item.
8. **Fix (low):** `SDIOutput.isOpaque` accounts for a gradient background's alpha; the plate honours its layer's opacity.
9. **Tests the review asked for:** the SDI readback test renders scene A then scene B and asserts the bytes change exactly (a stale-buffer regression would then fail); multi-verse packing under the default theme; the machine-specific golden digests skip, with a printed reason, when the recording machine's identity (macOS version and GPU name, hashed, no personal string) does not match, while the structural tests always run.
10. **Read and report, fix if wrong: the fill and key split.** The reviewer did not read `FillKeySplitter`. Check straight and premultiplied alpha for a frame with a semi-transparent plate, antialiased plate edges and text over the plate: fill colour values and key values for both modes, and that fill and key are produced from the same frame. Add tests for straight alpha if only premultiplied is covered.
