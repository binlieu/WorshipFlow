# UI-007c/d/e/f: the features that needed migration v15

Feature IDs: UI-007c (Edit), UI-007d (Media and Cues markers), UI-007e (Stage), UI-007f (Screens). Model: Sonnet. One agent per row, each in its own git worktree, at the same time.

SYS-015 (`AI/reports/SYS-015-report.md`, ADR-0009) added the storage, domain types and store methods; its report lists the exact public API per field. UI-006 (`AI/specs/UI-006-mode-features.md`) left these features out because the fields did not exist. Build them now. **Everything in the UI-006 brief applies here unchanged** (read it first: ranking by value, complete vertical slices, test-first, worktree rules, your files, no docs edits, commit to your own branch, Done means), with these differences:

- No further schema change, and no change to the v15 types' stored shape. If something is still missing in storage, list it; do not add it.
- Commit prefix `feat(UI-007<letter>):`, report `AI/reports/UI-007<letter>-report.md`, tests `UI007<letter>_*.swift`.

| Slice | Build, in this order | Notes |
|---|---|---|
| UI-007c Edit | **Layers list** (name, hide, lock, reorder, select) in the inspector at the design's place; a locked object cannot be moved, resized, nudged or deleted from the canvas and says why; a hidden one is not drawn anywhere (the compositor already skips it) and is shown struck through in the list. **Text Fit** (shrink to fit inside the object's frame, using the compositor's existing fit, with the same floor rules as lyric Fit) and **text Background fill**. **Video object**: place a clip from the bin as an object on a slide; it plays on Live inside its frame, looped and muted by default, through the existing media registry and render path, never decoding on the main thread; in Edit it shows a still frame. If the video object cannot be finished to that standard, leave it out and say exactly what the render path lacks. | Each edit is one undo step and never changes Live. Renderer changes: digest tests prove slides without the new values render byte-identically. |
| UI-007d Media + Cues | **Mark in and Mark out** on a clip (set at the playhead, type a time, clear), honoured by preview and by live playback (start at in, stop or loop at out) in the player and `MediaTransport`. **Markers**: add at the playhead, rename, move, delete, listed in time order in Media; in Cues, a marker's actions (CU-33 playback markers) run when live playback crosses it, fed by the real player position into the existing `MarkerTracker`, once per crossing, not on seek-over unless the design says so, never on preview playback. | You own `Media*`, `BinPlayer*`, `AudioPanel.swift`, `Cues*`, `CueSupport.swift` and the media engine files the playback rule needs. | UI-007e Stage | **Section element**: current section name and next section name from `ShowState.liveSectionName` / `nextSectionName`, as stage elements with a preset position, shown in Stage's element list and on the stage screen only. | Small slice. Then, with the room left: re-run the Stage rectangle comparison with UI-006e's new rows and extend `scripts/design-map-stage.json` (UI-006e did not). |
| UI-007f Screens | **Key destination label** separate from the fill label; **signal chain** per destination (operator-typed enclosure, converter, other nodes, drawn in the signal map as typed text, visibly labelled as the operator's own note, never as observed hardware); **per-screen Look** (a screen with its own Look uses it; others follow the global Look; the picker shows which applies and Looks deleted clear the choice, as the store already does). | Do not touch the SDI adapter, renderer or scheduler. Another agent (FIX-V) is changing `SettingsModel`'s remove-screen path and the output coordinator's retiring list: do not edit those functions. |
