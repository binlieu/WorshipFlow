# FIX-H: fixes from the independent review of UI-005a and UI-005b

Feature IDs: UI-005a, UI-005b. Model: Sonnet. One agent owns all files; it starts after UI-005i (the Inter font slice) is committed. No migration.

The independent review of commits 9417d09 and bbbea95 (2026-11-21) found no critical defect, two high and several medium ones. The decision for each is below. Work test-first and the order is checked: write the test, run it, see it fail at runtime (or fail to compile only for a symbol the fix introduces), then change the code; record the failing output per item. New tests in new files `FIXH_*.swift`. Do not edit existing tests.

## Items

1. **Fix (high): an announcements loop replaces a clip the operator just played.** The loop's tick only checks that some foreground exists. The loop ends, and the model is told, as soon as the foreground is not one of the loop's own assets, and when the operator plays anything to the foreground from the bin, the dock or a cue. Move the loop's decision logic out of the App target into `OperatorCore` behind the existing player port so it can be tested with a fake clock and fake player.
2. **Fix (high): Go Live or Next onto a media item while blacked out shows LIVE over a black screen, with the clip already running underneath.** Decision: taking a media, loop or sermon item live lifts Blackout, Cleared and background-hidden exactly as taking a slide live does, so the picture and sound start together where the operator can see them. Test Blackout, then Next onto a video item: Blackout is off, the item plays from its start.
3. **Fix (medium): switching or deleting the playlist while a media item is live leaves Next and Previous dead and the audio or loop orphaned.** End the live media item (from a stored copy of what it is, not a lookup in the reloaded list) before the playlist changes, and make Next and Previous fall through to the normal path when the item step finds nothing. Tests for select-other-playlist and delete-playlist with a loop live and with an audio item live.
4. **Fix (medium): Retry on a faulted mirror restarts the healthy primary too.** Restart only the faulted slot. Clear the "did not reopen" note when its card goes away. Use a fake coordinator that records which slots were restarted, not closure fakes.
5. **Fix (medium): a damaged or imported loop with zero seconds per picture crashes the one-second tick.** Decoding goes through the same clamping as the initialiser (custom `init(from:)`), the index computation guards against zero and non-finite values, and the program reader refuses or clamps out-of-range values in plain words. Look for the same pattern (validation in `init`, synthesized `Codable`) in the other types UI-005b added and fix each; list them.
6. **Fix (medium): a missing file shows LIVE with nothing playing.** The player reports success or failure; on failure the model does not mark the item live (or un-marks it), the operator is told which file, and the audience keeps what it had. An audio item with no audio player says so. Check the file is readable, not only that the bin lists it.
7. **Fix (medium): with the transport bar hidden, Space or Return on a focused control advances the live show.** Decision: when keyboard focus is on a control that is not a text field (a toggle, checkbox, segmented control, tab, slider, button or pop-up), Space and Return act on that control and the arrows act on a focused slider or segmented control; the show's transport keys apply when nothing or the slide grid has focus. Escape from a focused control returns focus to the show. Put the decision in the key-routing logic where it can be tested as a pure function of (first responder kind, key, sheet open), and add the cases. State in the hands-on checklist that this needs checking with macOS "Keyboard navigation" on.
8. **Fix (medium to low): custom controls.** `WFSlider` is focusable and moves with the arrow keys in steps; toggles, checkboxes and segmented controls dim and ignore input when disabled; `WFSegmented` identifies segments by index, not label. Every custom control exposes role, label, value and the right actions to accessibility; add what tests are possible at this level and list what needs VoiceOver by hand.
9. **Fix (low): a damaged prop targets value falls back to all roles including stage.** Use the documented default (audience and broadcast).
10. **Fix (low): prop pills and new text props.** A pill is a toggle: click turns that role off (drawn dimmed, still there) and click again turns it on; no right-click needed. A new text prop is saved switched off, and the sheet says "Saved off. Switch it on when you want it shown." Saving with no role chosen is refused with a line saying why.
11. **Fix (low): the LIVE chip in Edit, Stage and Screens is blank for a media item or loop,** and a loop ended by clearing the foreground still shows as live in the playlist. The chip shows the live item's title; the player's end callback clears the live mark.
12. **Fix (low): the seeded Looks do not apply to a screen added later.** A Look's per-screen entries fall back by role: a screen with no entry of its own takes the Look's entry for its role. Existing Looks behave as before for screens that have an entry.
13. **Fix (small): language names.** Quick edit labels use the presentation's stored language codes where it has them; detection from the words is only the fallback, computed when the slide changes and not on every redraw, and a detected name is shown as a suggestion ("Vietnamese?") only if it would otherwise be shown as fact. Say what the model stores today.
14. **Fix (small): a library from a newer build.** On opening a library whose applied migrations include one this build does not know, the app does not open it for writing: it says the library was last opened by a newer WorshipFlow, names both versions where known, and offers to quit or open a different library. Nothing is written. (GRDB may already refuse; make the message plain and test it with a library carrying an extra migration row.) This protects future downgrades; it cannot change builds already made, which is recorded as a known issue.
15. **Add the tests the review found missing** where not covered above: relaunch restore for each new item kind (never live by itself); the cue-executor and remote-state paths for the new item kinds.
