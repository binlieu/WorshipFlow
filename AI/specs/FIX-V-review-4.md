## Items, in this order

1. **M5: F1–F12 macro keys run before key routing,** so they fire with a button or toggle focused, in any mode including Edit and the Stage canvas, and in other windows such as Settings; a macro that runs Go Live or Blackout can fire from a stray key press. Decision: a macro key is a routed command like every other show key. It goes through `KeyRouting` as its own decision and runs only when the main operator window is key, no sheet, popover, menu or alert is up, and focus is not in a text field or search field; a focused button or toggle does **not** block it (an F-key is not Space or Return) but another window (Settings, a stage or output window, the remote panel) does; it never runs on key repeat or with a modifier. In Edit, Stage and Screens modes macro keys are **off unless** the macro bar's trigger shows them as armed there: simplest truthful rule, to decide and state: macro keys work in Show and Cues only, and the Trigger menu says so. Every run shows in Activity as "key". Tests on the pure routing function for every focus kind and mode, and a run through the debug hook with real key events in each mode.
2. **M4: Remove screen** is refused while that screen's output is running or it is the only screen of its role that is on air (message says to close the screens first); the confirmation names what goes with it (its Look entries, its stage layout choice, cues that target it: count them); the stage layout choice and any other per-screen setting is removed with it, leaving nothing orphaned. Cues or Looks that referenced it show as "screen removed" (broken step), never retarget silently.
3. **M3: `removeSection` and `moveSection` act on a row position from the view;** two quick edits can remove or move the wrong section and leave the song's playing order wrong. They take the section's identity, re-find it after any await, and are a no-op with a message if it is gone; one undo step each. This is user data: test the interleavings FIX-T's report listed.
4. **M2: the output coordinator's `retiring` list is only emptied when an SDI output starts or a waiting stop is asked,** so on display-only setups every Close screens, Retry or profile change keeps a stopped output (window, Metal layer, textures) alive for the life of the app. Each retired output is released when its own teardown completes; test that after N open/close cycles with display outputs the list is empty and the outputs are deallocated (weak reference check). This is in the output path: one small change, described in the report; SDI behaviour (start waits for the retired port) must be unchanged and its existing tests untouched.
5. **M1: Edit's Stage preview always draws the built-in Standard layout,** ignoring the stage screen's chosen layout, Hide, Auto-fit and the "next" line. It must compose with the same inputs the real stage screen gets (the selected layout for that screen, the next slide), through the same composer; speaker notes stay out exactly as they do today only if the real stage scene shows none: if the stage layout has a notes element the preview shows it, because the preview is of the stage screen and is never an audience or broadcast scene. Test by digest: preview scene equals the stage screen's scene for the same state.
6. **Low findings:** fix each that is confirmed and small: hot-folder items added to a collection then silently pruned (refuse the add with a message, or keep the reference; choose and say); collections, macro keys and the Cues slide-action list being overwritten or going stale (read-modify-write on app state must not drop a concurrent change: re-read inside the write or serialise the writers); the Media offline check running at every app activation (run it only if the bin or the mounted volumes changed since the last check, or at most once per activation burst; nothing may tick while idle); destructive dialogs drawn red (red is only for on air: use the muted destructive style the app uses elsewhere, and say if this is a system dialog you cannot restyle). List the rest as known issues text for the coordinator, including "Stage layouts lose Hide and Auto-fit when an older build saves them".
