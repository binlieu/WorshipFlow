## Items

1. **"when click in the media bin video, just change the video of the LIVE only, don't apply it to the current slides".** Find what a click in the bin does today and say so in the report. Required: choosing a clip in the bin (as Background or Foreground, by the existing switch) changes what is LIVE now, as a live override. It never writes to the open presentation, its slides or its theme, and it does not change Preview. The override stays while slides advance within the presentation and is replaced by the next bin choice; state in the report what happens when the next playlist item goes live (decision: the override stays until cleared or replaced, and the inspector shows that an override is on, with a button to drop it and return to the slide's own background).
2. **"have feature to clear LIVE background / foreground / lyric / music".** Four separate live clears, each reversible in the sense that the next Go Live or bin choice brings content back: Clear lyric (the words; this is today's Clear), Clear background, Clear foreground, Clear music (the audio player, not a video's own sound). They live in the Clear menu of the transport bar next to Clear all, each with a keyboard shortcut that does not clash with the table in `CuesMode` (add them there), and each goes through the one serial command path so cues, MIDI and the remote can use them later (add the commands; wiring them into the cue editors' action list is in scope if it is a list entry, not if it needs new UI). Blackout semantics are unchanged. Clearing a layer cancels nothing else.
3. **"the audio cannot unmute while the video is background".** Reproduce at model level first. A background video is muted by default, which stays, but the operator must be able to unmute it from the controller, and the state shown must be the state heard. Blackout still silences it and restores the chosen state afterwards.
4. **"in the media bin, when select media, the right sidebar should show the player (video / music / picture ) with player controller".** Selecting an item in the bin (single click selects; say in the report how select and "send live" are told apart, decision: single click selects and shows it in the inspector, double click or the Live button sends it live as in item 1) shows it in the right sidebar: a video with play, pause, scrub, time, loop and mute; an audio file with the same minus the picture; a picture as a picture. This player is a local preview on the operator's Mac only: it never reaches an output and its sound follows `--silent-audio`. From there: Send to live background, Send to live foreground, and for audio Play live.
5. **"add hot folder so I can point to the folder to run the videos in that folder".** The operator points the bin at a folder. Its videos (and pictures and audio) appear as a source in the bin and stay in step with the folder as files are added, renamed or removed, without restarting. "Play folder" plays its videos to the live background or foreground one after another in name order and loops. Access survives relaunch through a security-scoped bookmark; a folder that is gone shows as missing with a way to point it again and never blocks the show. Files are never moved, copied or deleted. Several hot folders are allowed. A file being copied into the folder is not played until it is complete (size stable).
6. **"drag and drop video to individual slide to customize slide background if needed".** Dropping a video (or picture) from the bin or from Finder on one slide thumbnail in Show or Edit sets that slide's own background. This is an edit to the presentation (unlike item 1): it is saved, undoable, shown by a small mark on the thumbnail, and removable ("Use the presentation's background"). When that slide goes live its background is used unless a live override from item 1 is on. Editing an inactive slide never changes Live. If the schema needs a column it is migration v11, additive only; check first whether the slide model already carries a background.
