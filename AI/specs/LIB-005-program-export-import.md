## What to build

1. **A program package.** One file the owner can carry on a USB stick or send: a folder package with the extension `.worshipflowprogram` (declared as a document type and exported type of the app, so Finder shows it as one file), containing `program.json` (a format name, a format version, the app version that wrote it), the playlist with its items in order (songs and presentations with all slides, sections, languages, notes, slide actions and per-slide settings; headers; countdowns; scripture items as reference and translation codes only, never Bible text), the themes and Looks those items use, and a `media/` folder holding a copy of every media file the program refers to (backgrounds, foregrounds, pictures, audio, clips in the playlist). Every reference to media inside the package is a path relative to the package, never an absolute path, a bookmark, a user name or a volume name.
2. **Export.** File menu "Export Program…" and the playlist's menu: choose a playlist, see what will be included with total size and anything missing (a media file that cannot be read is listed; the operator may export without it and it is recorded as missing in the package), then write. Writing is atomic: build in a temporary sibling folder and move into place; a failed or cancelled export leaves nothing half-written and never touches the library. Progress is shown and it can be cancelled. Media is copied (cloned where the file system allows), with identical files stored once by content hash.
3. **Import.** File menu "Import Program…", opening a `.worshipflowprogram` from Finder, or dropping one on the window. A summary first: what is new, what is already in the library. Items carry stable ids: an item whose id and content match is not duplicated; an item whose id exists with different content asks once for the whole import: keep mine, use the imported one, or keep both (the imported copy gets a new id and " (imported)" in its title). Default and safest choice: keep both. Media is copied into a managed folder next to the library (`Media/Imported/<program id>/`), referenced from the library relative to the library's folder, so it still resolves after the library folder is moved; an identical file already there is reused. The import is one database transaction: any failure leaves the library exactly as it was and removes the files it copied. A scripture item whose translation is not installed imports and shows the existing "translation not installed" state.
4. **Safety.** A package is untrusted input: refuse paths that are absolute or escape the package (`..`, symlinks pointing outside), refuse a `program.json` over a sane size, unknown format versions newer than this build are refused in plain words, older ones are read. Nothing in a package can make the app read or write outside the package and the library's own folders. Never overwrite a file on export or import without asking.
5. **Round trip.** Export from one library, import into an empty one: the playlist plays the same, slide for slide, with every background and clip found. Export on a Mac where media sits on an external volume, import on a Mac without that volume: everything resolves from the copied media.

Put the format and the read and write logic in the package (a new target or within `Persistence`, with no SwiftUI import) so it is testable; the app holds only the sheets and menu items. A new package target may edit `Package.swift` and `project.yml`; you are the only task allowed to.
